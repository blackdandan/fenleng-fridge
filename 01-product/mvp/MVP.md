# 冰箱库存管理 · 已确认产品方案

版本：V0.4 工程交接；日期：2026-11-13。Owner 已明确承接现有 MVP，新增微信小程序及 HarmonyOS NEXT 范围；App 同时支持 Android、iOS、HarmonyOS NEXT，Web 仅为官网。产品正式名称待定，面向个人。当前已交付仍是本地 Web 交互原型与 Figma 稿，不是可安装 App 或可发布小程序；交接不代表功能验收通过。详见 `../handoff.md`。

## 核心价值与路径
用照片记住家中食材，在少填写信息的前提下持续核对库存。
首页两层可视化柜体（上层冷藏，下层左冷冻、右常温） → 点击储存区域 → 直接查看库存 → 食材入库或整理食材。区域页两项操作同等高频，按钮等宽各占一半。

## 入库
- 一种食材一张照片，一张照片一条记录；不要求名称与数量，不做食材识别或包装日期识别。
- 当前区域决定默认保存方式，连续拍照即入库，相机保持打开；切换区域只影响之后拍摄。
- 支持相册多选，每张独立生成记录；入库日期按添加时间，自动生成稳定编号。
- 自动记录照片、编号、入库时间、保存方式、检查间隔与下一次提醒。字段可在详情调整。
- 误拍允许重拍替换或直接删除。照片与库存仅存本机，不上传食材照片、不做云同步与换机恢复；卸载或清除数据会丢失记录。无需填写账号密码；同意隐私政策后拟由 Shared Platform 无感建立游客身份，用于反馈和产品分析，不意味着库存上云。当前游客登录契约缺口见 `shared-platform-integration.md`。

## 首页
- 两层简洁柜体示意：上层冷藏占满宽度；下层左冷冻、右常温等宽等高、边缘对齐。非拟真复杂插画；圆形食材照片是主体，稳定排列；新增、移除、移动时平滑补位，不持续漂浮。
- 每个非空区域入口文案统一为「点击管理食材」，与箭头相邻并整体居中对齐。空区域按下述正式产品空状态规则处理；当前预览暂不调整。
- 每个区域显示仍在库的照片和记录数。超过容量显示 +N，进入区域查看全部。记录数不是物理体积或精确食材数量。
- 首页仅保留「我的冰箱」标题、右上角并排的提醒铃铛、设置入口与可视化柜体；不设底部导航，通知必须可从首页直接进入；移除标题日期、总体记录数、「食材都在这里」、圆图解释文字、最近记录卡片和底部操作提示。各区域自己的记录数保留。
- 无产品名、无营销文案、无购物清单。

## 空冰箱与空区域（正式开发需求，当前预览暂不实现）
- 适用于首次安装、尚未入库，以及某个区域的在库记录全部移出后的状态。
- 冰箱和三个区域完整保留，位置、大小与有库存时一致；不展示示例食材或虚构库存。
- 空区域保留名称，隐藏「0 条」，区域中央显示淡色「＋」，底部入口显示「拍照入库」。
- 点击空区域任意位置，直接进入拍摄页并默认选中该区域，跳过空列表和再次点击入库的步骤。
- 第一张照片入库后，对应区域显示圆形照片与记录数，入口变为「点击管理食材」；未入库区域继续保持空状态。
- 不额外显示新手教程、大段空状态文案或强制引导；没有在库食材时不提示整理库存。
- 用户明确要求本轮仅记录此设定，保留当前带示例库存的 preview；这些条目尚未实现或验收。

## 整理
- 四种绝对剩余状态：都在、剩一半、剩少量、没了。
- 前三种保留当前库存，并更新已点选记录的确认时间，按该记录间隔安排下一次检查；不改变最初入库时间。
- 都在表示恢复完整状态，而不是保留前次剩一半；剩一半重复点选仍是剩一半。
- 没了移入历史，取消其提醒，支持撤销和恢复；不区分吃完与扔掉，不做浪费统计。
- 未操作的记录保持不变，完成整理不代表批量确认。
- 移动储存区域只更改位置，不覆盖时间或自定义间隔；时间遵循通用编辑功能，不另设计移动计时。

## 提醒
- 冷藏默认3天、冷冻14天、常温3天，按17:30安排检查。全局默认与单条记录可改；更改全局默认不覆盖已有记录。
- 只有到检查时间才触发本地通知，同一天合并，每个检查周期仅通知一次。无每日固定Push、无未处理3天重复催促。
- 未处理记录保留待检查；用户处理后开启该记录下一周期，没了后不提醒。
- 超过2天未整理且仍有在库食材时，首页显示「这两天没做饭吗，冰箱的食材还能吃吗？」及「去整理」按钮；仅作App内提醒，不发送系统通知。点选四种整理状态算实际整理，浏览、入库或修改设置不重置最近整理时间。
- 已有食材达到检查时间时，首页优先显示「放太久了，这些食材还新鲜吗？」及「去整理」按钮，不叠加两种卡片。这里的到期仍指检查时间，不是确认食品过期。
- 两种卡片的「去整理」均直达全部在库食材整理页，覆盖冷藏、冷冻、常温，按待检查优先排列，显示储存区域。历史不混入；仅操作已点选项，不自动确认整页。返回回到冰箱首页。
- 检查时间不是保质期，不提供食品安全结论。
- Web预览仅演示通知样式、调度状态和模拟时间，不请求浏览器系统通知、不声称iOS/Android本地通知已实现。

### 通知处理闭环（V0.2.2 补充，待实现与验收）
- 按本地自然日合并检查提醒，同一天陆续到检查时间的食材归入同一条提醒，更新条目而非新增重复提醒；不同日期分别保留。跨多天推进模拟时间时，按各食材原定检查日期归并。
- 每条提醒关联具体食材及其本次检查周期，同一周期只通知一次。通知中的原始提醒数量保留，同时展示当前剩余待处理数量。
- 待处理须同时满足：食材仍在库、仍属于该次检查周期、已经到检查时间。查看通知不等于处理，不重新计时。
- 点击提醒只进入该提醒尚未处理的食材列表。部分处理后更新剩余数量；最后一条处理完，显示「本次提醒已处理完成」，提供返回提醒列表入口，不显示区域无库存的误导文案。
- 通知列表区分待处理、部分处理和已处理。全部处理后保留通知历史，显示「已处理」，移除整理入口；历史原始数量不冒充当前待处理数量。
- 首页铃铛红点表示仍有待处理提醒；全部处理后消失，不因存在历史通知而持续显示。
- 「都在／剩一半／剩少量」结束该条本次检查周期并安排下一周期；「没了」或删除使其退出待处理。手动修改下次提醒时间结束旧安排，按新时间等待提醒，不回填旧通知。
- 移动区域或仅修改检查间隔不解除当前待处理状态；间隔仍用于之后整理时的下一次安排。恢复历史记录产生新的检查周期，不重新激活旧通知；撤销操作按恢复后的记录和周期重算通知状态。
- 新周期到期可再次提醒，旧通知不得引用新周期的待处理状态。刷新或重新打开后保留通知与处理结果。
- 原型验收覆盖：同日分批到期合并、跨日提醒、重复检查不重复通知、部分及全部处理、红点消失、完成页返回、改期/删除/恢复/撤销、新周期提醒及刷新持久化。拍摄和通知采用模拟符合原型定位，验收以规则与交互闭环为准。

## 历史与数据
不设底部Tab；从首页右上角进入设置，历史记录从设置进入，各子页面提供顶部返回。历史记录保留直到用户主动删除，可恢复；永久删除需明确确认。原型通过浏览器本地存储示意本机保存，支持重置演示，不承诺与原生App相同的数据耐久性。

## 后续实现边界
相机/相册授权应在使用时申请，拒绝时可切相册或前往系统设置；预览不仿造操作系统权限弹窗。三端原生权限、通知及微信能力、安装包与设备验收属于后续工程实现。

## 首次进入与协议
- 第一次进入首页前，展示应用自己的「用户协议与隐私政策」说明，提供两份全文入口及「同意并继续」「暂不同意」。不预勾选，不将浏览、返回或关闭视为同意。
- 说明照片/库存本机保存、无感游客身份、反馈和关键行为分析，不笼统宣称完全离线或完全不收集数据。
- 同意前不启动联网身份、反馈提交、SDK 数据采集，不申请相机或通知权限。暂不同意进入可再次阅读/选择的说明状态，不进入库存功能；原型不关闭浏览器。
- 记录协议版本与确认时间；仅重大处理规则变化时重新征求同意。查看全文后回到原来的首进步骤，不能绕过同意；已同意重进不重复弹窗。
- 不提供单独的产品分析同意开关。埋点用途与范围纳入统一隐私告知；整体隐私授权撤回可从隐私政策页发起，说明停止联网服务与分析、清除待发队列并回到首进说明，本机库存不自动删除。

## 拍摄权限解释
- 视觉约定（2026-11-13）：拍摄为独立页面；真正弹窗左右至少16px留白，相机解释/拒绝说明从页面顶部16px弹出。Owner 已验收 Figma 视觉，按该稿实现；旧 Web preview 保留为参考。
- Android 点击「食材入库」且相机未授权时，先展示应用解释弹窗：标题「相机权限使用说明」；正文「用于拍摄食材照片并保存在本机，帮助你记录冰箱库存。不会上传食材照片，也不会录音。你也可以选择相册图片入库。」
- 操作「继续申请」「使用相册」「暂不拍摄」；只有继续申请才触发 Android 系统权限请求，不在首次进入首页时提前申请。
- 已授权直接进入拍摄；拒绝后可再次主动申请或使用相册；系统不允许再次弹出时提供前往系统设置及相册替代路径。设置返回重新检查权限，未授权不误报成功。
- 原型展示真实应用解释弹窗；授权/拒绝/受限由明确标注的演示控制模拟，不仿造 Android 系统弹窗。相册优先系统图片选择器，仅处理主动选中的图片；不为相册索取无关权限。

- 默认检查设置、历史与演示控制之后，最底部固定收尾顺序：用户协议、隐私政策、反馈；再下方居中低强调显示本 App 备案号。备案文字仍可读，不使用极小字号或低对比度隐藏。

- 协议全文可从设置反复访问，返回设置；与首进说明、官网使用同一版本正文。
- 反馈包含必填意见、提交中、成功回执、失败重试，失败保留草稿；重复点击不重复创建，重试复用同次提交标识。返回未提交时保留草稿。初版不收集截图、日志或联系方式附件。
- 正式反馈使用 Shared Platform 与官方 Client SDK；响应确认后才提示成功。无感身份未就绪或断网时不影响库存，反馈可保留后重试。原型仅本地模拟回执，不声称意见已送达。

## 无账号密码使用
- 不出现注册、账号密码输入或强制第三方登录页。接受隐私政策后后台建立或恢复应用隔离的游客会话；失败时保留离线库存功能，并在反馈操作时给出重试路径。
- 游客身份不提供跨设备身份恢复或库存恢复；清除应用数据可能产生新身份。不得用硬件标识、通讯录或静默收集手机号拼接身份。
- 当前 Shared Platform 存在 GUEST 模型与会话恢复，但尚未找到公开游客会话创建契约；此项为正式开发前上游待补能力，不声称已接入。原型只模拟身份状态。
