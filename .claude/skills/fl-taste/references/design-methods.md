# Taste 方法的 Fenleng 适配

本文件改编自 Taste 的 brief inference、design engineering、pattern vocabulary 和 redesign protocol。MIT 许可及固定版本见同目录 provenance.md、upstream-license.txt。

## 从意图到构图

先区分新建、保留品牌的改良、已授权的视觉重做。已有界面先看截图和运行行为，记录品牌、导航、主路径、内容、断点、状态、事件与无障碍基线。

选择一个主构图，并解释为什么另一个候选不适合。不要用假随机数、模拟执行输出或骰子替代判断。

| 场景/内容 | 可选择构图 | 实现要点 | 手机回退 |
| --- | --- | --- | --- |
| 一条价值主张和强产品素材 | 非对称 split | 文案宽度由实际字数决定；画面与 CTA 共用对齐线 | 文案→主操作→素材，避免横向溢出 |
| 内容或宣言本身最重要 | editorial manifesto | 通过字体重量、行宽、节奏制造焦点，不强制加图片 | 自然换行，避免逐字断行 |
| 不同优先级的功能/作品 | 有主次的 bento | 一个主区域，次级区域成组；验证 span 和真实内容，没有孤立空格 | DOM 顺序与阅读顺序一致，不靠 dense 重排交互控件 |
| 专业工作区 | 导航＋工作列表＋上下文面板 | 主操作临近工作对象；用行、分组及空白组织，减少卡片套卡片 | 面板移为次页/抽屉，保留主任务 |
| 长叙事或案例演示 | 章节＋静态媒体；必要时 sticky stack | 只有叙事需要才 pin；内容先可读，动效后增强 | 正常文档流；减少动效时全部可见 |

相邻章节改变内容组织方式，而非只轮换左右图片。保留同一对齐网格和主题，表现力集中在一两个关键区域。

## 排版与表面精修

- 标题先调容器宽度、文案和层级，再调字号；桌面营销标题尽量两三行，但中文、字体放大和小屏优先完整可读，不硬性裁切。
- 检查孤字、斜体下伸部裁切、标题与正文基线。长正文限制行宽；数据列用 tabular-nums 并对齐单位。
- 项目已有字体可继续使用。新字体需覆盖实际语言并有可用资源；不能机械禁用 Inter、衬线或系统中文字体。
- 颜色保持主题中的主强调语义；成功/错误等反馈色仍保留，不能为了“单强调色”把状态全部染成品牌色。
- 圆角遵守组件层级和 Token；分组优先空白/分隔线，只有表面层级确实需要时使用卡片或阴影。
- 并排比较区域对齐标题、价格/数值、列表起点和操作。调整布局不要靠每项硬编码高度掩盖长文案问题。

## 素材与文案

- 图片承担真实职责：展示产品、解释步骤或表达已确认品牌。优先项目资产/真实截图/可运行组件预览；需要新插画或照片时按宿主图像工具能力生成并查看成品。
- 不把任意占位照片宣称为品牌实拍；不伪造客户、评价、经营数据或产品能力。示例数据显式标注。
- 图标沿用项目现有库、笔画和尺寸。不要为追求“独特”无理由更换依赖。
- 删除无信息量的编号、角标、装饰状态点和口号；真实步骤编号、运行状态与必要版本信息保留。
- 每个可见文案都要重读：主操作写具体动作，错误说原因和恢复办法。保留原有品牌语气和真实事实。

## 旋钮必须变成可见行为

- Variance 1–3：稳定对齐与可预测结构；4–7：不同区域比重、素材比例或留白；8–10：仅在创意场景采用显著非对称，提供手机回退。
- Motion 1–3：hover/focus/pressed 微反馈；4–7：有目的的进出场或状态过渡；8–10：仅在任务需要时用滚动叙事。时间曲线取已有 Token。
- 不给静态页面虚标 Motion 7。Motion/GSAP 只管理其拥有的元素；组件卸载清理监听、timeline 与 observer，减少动效时内容不能隐藏。
- 不强制新装 GSAP、React 或 Tailwind。原生端用原生动效，Web 优先现有栈；连续输入避免逐帧更新整个 React 树。
- Density 的上游数字只表达意图，FL 实现必须声明 Standard/Compact 和实际组件密度，触控目标不缩小。

## Figma 交接与视觉验收

交给 Figma 的设计说明包含：构图理由、组件实例、变量绑定、Auto Layout/约束、断点、状态及素材来源。审查既看截图，也看组件/变量是否真实绑定。只有有写入能力的 Figma 工具才能修改画布，不能把 HTML 截图称为 Figma 交付。

对真实交付运行以下闭环：

1. 在目标端实际渲染；至少检查最窄支持视口、桌面或目标设备，以及相关明暗主题。
2. 对比同内容、同视口的前后图：焦点、层级、对齐、换行、留白、素材和密度，每项给位置与观察，不虚构分数。
3. 操作主路径，覆盖适用的 loading/empty/error；键盘可达、焦点可见、弹窗可关闭、失败可恢复。
4. 查看减少动效模式、长中文和放大字体；检查横向溢出及固定栏遮挡。
5. 修正发现的问题并重新渲染。记录残留缺口；没有截图/真实操作证据时只标记方案待验收。

## 对上游的明确适配

保留构图词汇和具体审查动作；不继承模拟 Python 执行、所有页面强制 AIDA、禁用所有静态页面、强制外部占位图、编造精确数据、无条件禁用字体/标点、强制新 UI 框架。这些规则与真实产品语境、诚实验证或 Fenleng 已有规范冲突。
