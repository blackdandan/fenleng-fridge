# Conversational MVP Definition Rule

## 适用场景

当 Agent 通过对话帮助用户定义 MVP、PRD、功能范围、用户流程或产品验收标准时，必须遵守本规则。

## 核心原则

MVP 定义不是一次性文档生成，而是产品经理式澄清、收敛和确认过程。

Agent 应通过对话理解用户想法，并把模糊想法逐步收敛为可执行、可验证、可交接给后续技术规划的产品定义。

## 对话规则

- Agent 必须像资深产品经理一样追问，不得机械输出问卷。
- 每轮优先询问当前最阻塞 MVP 定义的问题。
- Agent 应主动总结用户回答，并指出范围取舍。
- Agent 应识别需求膨胀、伪核心功能和第一版不必要复杂度。
- Agent 不得在信息不足时假装已经完成产品定义。
- Agent 必须确认本次产品稿件的目标读者和表达风格。默认 PRD 同时面向研发团队与客户/业务方，文档风格为可执行版；默认 Preview 面向最终用户体验，而不是内部线框图。
- Agent 必须确认 Figma 视觉稿的用途、目标设备、页面范围、视觉风格、禁用文案、品牌约束和输出格式。若用户希望用 Figma 生成视觉，最终必须交付版本化 Figma Prompt。
- Agent 必须维护 MVP 本体版本记录 `docs/mvp/version-history.md`。任何范围、页面、文案、Preview、Figma Prompt 或完成状态变化，都必须新增版本记录或追加变更条目。
- **图表数据精确定义**：凡涉及数据可视化（如折线、柱状、饼图等图表），Agent 必须追问并理清图表类型、横轴含义与单位、纵轴含义与单位、数据颗粒度、交互细节，以及产品设计决策推演（Why），拒绝“泛泛而谈”的模糊表达。

## 必须覆盖的问题域

- 目标用户。
- 核心问题。
- 当前替代方案。
- MVP 核心假设。
- 最小价值闭环。
- 功能范围和非目标。
- 用户路径。
- 页面、状态（默认、空、错误状态）和关键反馈。
- 可视化图表规格（横纵轴含义与单位、时效频率与产品设计决策推演）。
- 产品验收标准。
- 成功判断和失败信号。
- 目标读者、文档风格、Preview 面向对象和用户期待优先级。
- Figma Prompt 的使用对象、版本策略、页面清单、组件状态、视觉约束和禁止项。
- MVP 当前版本、完成状态、状态变化原因和完成 Gate。
- 产品 Surface 范围（Flutter App、Web、Taro 小程序）；涉及小程序时确认微信、支付宝、抖音的 P0/P1/Later、平台权限和差异能力。

## 生成前完整性 Gate

正式落盘前，Agent 必须检查并向用户摘要确认：

- 用户、问题、场景和当前替代方案是否明确。
- P0 是否足够小，Out of Scope 是否明确。
- 主用户路径是否从进入到获得价值闭环。
- 页面范围、默认/空/错误/成功状态是否齐全。
- 数据、图表口径和 Mock 数据是否足以支撑 Preview。
- 产品验收标准是否可判断，成功/失败信号是否可复盘。
- PRD 是否能让研发理解如何进入后续技术规划和开发拆解。
- PRD 是否能让客户/业务方理解产品价值、范围和体验结果。
- Preview 是否能让最终用户看懂首屏价值、核心 CTA、主路径和反馈状态。
- Figma Prompt 是否能独立指导 Figma 生成视觉稿，并明确禁止出现的页面入口、文案和范围外承诺。
- `version-history.md` 是否记录了当前 MVP 版本、完成状态、最近变更、完成 Gate 和未完成原因。
- `surface-scope.md` 是否与页面、Preview 和 Figma Prompt 一致；小程序是否区分基座支持、应用认证和平台差异。

如果 Gate 未通过，必须继续澄清，不得进入正式落盘。

## 正式落盘规则

- 用户未明确表示“可以生成”前，不得写入正式 MVP 文档或 preview。
- 正式落盘前，应先给出 MVP 草案摘要供用户确认。
- 生成后如用户反馈修改，必须更新对应文档，并保留关键判断记录。
- 生成后如用户反馈修改，必须同步更新 `docs/mvp/version-history.md`。用户未明确确认工作流结束时，当前状态不得写为 `completed`。

## 结束规则

- 只有用户明确确认“流程结束”“MVP 定稿”或等价表达后，本 Skill 才能结束。
- 用户未确认结束时，Agent 不得宣称流程完成。
- `docs/mvp/version-history.md` 中的 Completed 只有在用户明确确认结束后才允许写为 `Yes`。

## 职责边界

本文件不允许 `fl-mvp-definition` Skill 负责以下内容：

- 技术架构设计。
- 数据库设计。
- API 设计。
- 代码目录规划。
- 具体开发任务拆分。
- 真实后端、真实接口或线上部署。

如果用户提出这些内容，Agent 应说明边界，并建议进入后续技术规划流程。
