# 华为 HarmonyOS 应用上架

核验日期：2026-10-15。官方[分发入门](https://developer.huawei.com/consumer/cn/appgallery/devstart/)、[提审准备](https://developer.huawei.com/consumer/cn/app/submit)、[DevEco 发布应用](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-publish-app)（当前跳转到 doccenter-deveco-studio 同名文档，页面更新 2026-10-10）。提交前在当前开发者中心核验文档及软件包检测。

独立使用 `huawei-harmonyos` 目录、HarmonyOS 应用记录与真实 bundleName，不借用 Android 包名、截图或已过审结论。先核对账号实际权益、App ID、bundleName、APP 备案对应标识、证书/Profile 和应用记录一致性。

## 软件包与运行证据

模拟器安装的 HAP、release 文件名、使用官方签名工具成功都不能证明可提交商店。按当前 DevEco/AGC 发布说明核验应用发布形态 APP Pack（.app）和发布签名流程；记录实际 SDK/IDE 版本、产品/模块、版本号、发布证书/Profile 类型和平台包检测。不要把 .hap 改扩展名冒充 .app，也不要上传调试 Profile 冒充发布签名。当前 IDE 支持云管理签名时按既有项目通道使用，不擅自替换上传方式或轮换密钥。

本轮 SDK 26.0.0.105 的实际发布验证表明：仅将已签名 HAP 装入未签名 APP 容器会得到合法性错误 991；HAP 签名可验证不能证明 APP 容器已签名。使用项目既有发布身份完成 APP 容器签名，再对最终 APP 执行官方 `hap-sign-tool verify-app`，最后以平台合法性报告判断。保留包型、SDK 和签名层级，不能把此结果推广为所有旧 SDK 的固定参数。官方[错误码说明](https://developer.huawei.com/consumer/cn/doc/doccenter-submission/agc-help-package-errorcode-0000002312513009)也要求检查未签名或手动拆装包导致的签名问题。

手动使用官方打包工具时核对 `pack.info` 的 packages.name 与内含 HAP 文件名；若 HAP 已签名，避免随后改写其内容。本轮 `replace-pack-info true` 会改动 HAP 字节，不能据原签名结果继续宣称有效。签名参数和兼容 API 从实际工程取值，不在上架 Skill 保存私钥或口令。

平台解析成功后，启动上架自检并记录实际任务状态；“合法性已达标”“检测中”“检测通过”“已选入版本”“草稿保存”“已提交审核”分别取证。进入准备提交页后还须选取软件包，不以软件包管理中存在文件代替版本关联。发布地区、会员等真实资费、协议、年龄分级、备案主体和负责人验证均以本次表单填写；不沿用默认全球分发或未经本次确认的数据出境声明。

从当前真实 HarmonyOS App 获取截图并核验对应设备组。检查启动、隐私同意、存储、文件、扫码、登录、支付、取消、回跳及重启恢复，记录模拟器和真机各自覆盖范围；缺真机证据不得声称已通过真机。不能用 Android/iOS 成功替代鸿蒙运行证据。

按 HarmonyOS 当前实际登录 Provider 和支付路径填写说明，不披露不存在的 Google/Apple 入口。付费能力和商店要求分别核对；支付宝模拟器付款成功不自动证明华为渠道资费或支付要求已满足，也不代表微信真机回调已验证。

## 控制台流程

查找/创建对应 HarmonyOS 应用 → 本地化名称、分类和介绍 → 本设备截图和图标 → 备案、版权及授权 → 隐私及权限 → 发布包上传和平台检测 → 审核账号/联系信息 → 选择地区/发布方式 → 提交审核并记录回执。图文规格和必填资质取当前表单，不套用 Android 分支。

按新渠道三层资料模板分别输出同市场初次和版本文件；构建记录含 bundleName、App ID、versionName/versionCode、设备类型、min/target API、模块清单、包大小与 SHA-256、证书/Profile 和平台处理状态。暂只有 HAP 时明确记录发布包缺口，继续完成独立资料。

## 提审资料按页面顺序交付

在初次资料顶部列出“后台区块 → 可粘贴字段/本渠道附件 → 本次保存证据 → 缺口/下一步”的清单。依次覆盖本地化信息、截图、软件版本、资费、内容分级、隐私标签、AI声明、版权、应用内商品、备案、审核登录、负责人验证和发布时间。Owner只要求准备资料时不提交；仍完成能独立完成的资料和草稿，不因单一备案或验证码缺口停止其余准备。

当前手机表单截图快照：3~10张；竖屏9:16、最低1080×1920，横屏16:9、最低1920×1080；PNG/JPG/JPEG每张不超过5MB，WEBP不超过200KB。运行截图归档时记录实际分辨率、是否调试标记、对应构建和画面内容。带DEBUG标记或不符合比例的原图只能标记为运行证据；不得直接宣称可提交，也不能拿其他平台图填补。AppScope图标和EntryAbility的icon/startWindowIcon都需核对，旧debug HAP可能仍含默认图标，不以release包已修正推断模拟器安装也已修正。

备案校验按当前鸿蒙bundleName进行。Android同主体、同备案号校验通过不证明鸿蒙包名已登记；2026-10-16实际提示“鸿蒙版、安卓版包名需要分别完成备案”。核对原备案中的平台、包名、公钥/签名及应用标识是否覆盖本次身份，保存后台具体失败原因，必要时补充变更备案。失败原因列表不是已证明唯一原因；未查原备案前不得断言一定缺少备案，也不擅自改包名、换主体或重签。

版权材料在本渠道归集并逐项选择正确栏位：纸质软著逐页图片用于应用版权证书图片栏，电子版权证书PDF栏不混用。记录个人权利人、个人开发者与备案经营主体的真实关系，授权文件按本次平台要求准备，不复用其他商店专用签章文件。隐私标签只声明鸿蒙最终包实际采集与第三方处理，不照搬Android传感器或Provider。

最终资料交付必须区分：已准备本地附件、已填保存、平台校验通过、外部办理缺项、未提交。审核口令留在平台私密字段；仅记录交付状态。备案、验证码、真实签署或设备问题写明具体动作和恢复入口，不能生成空占位文件冒充完成。


## 现有签名与账号归属

实名显示名、联系邮箱、开发者 ID 和 APP ID 是不同字段。身份疑问先读开发者信息页，再将实际开发者 ID 与现有 Profile 的 bundle-info.developer-id、bundle-name、app-identifier 比对，并查询该账号的 APP ID 列表；不能仅凭实名显示名推断登录错账号。若原签名属于另一开发者，先查清申请来源和已有应用，不用新注册、改包名、换签名或覆盖旧草稿自动消除差异。
