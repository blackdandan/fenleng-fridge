# Source Code Material Authenticity Rule

## 适用场景

当任务涉及软著源程序鉴别材料的源码筛选、生成、排版或审计时，必须遵守本规则。

## 核心原则

源程序鉴别材料必须来自真实项目源码，并能够解释其对应的软件核心功能。材料生成的目标是清晰呈现软件的原创性表达，而不是制造通过审查的假象。

## 必须执行

- 记录源码根目录、入选文件、排除文件和排除原因。
- 默认优先选择一个端的核心业务代码作为源程序鉴别材料范围，避免把 App、后端、管理端、网关和公共模块混合成难以解释的材料。
- 如确需同时纳入客户端、服务端或共享模块，必须满足它们同属同一申请软件、软件名称和版本一致、说明书能解释端到端功能关系，并在源码筛选说明中标注各端来源。
- 优先选择体现核心业务逻辑、核心算法、关键交互、数据处理或特有流程的源码。
- 排除或降权测试代码、生成代码、第三方依赖、通用脚手架、通用 CRUD、登录鉴权、实体类、DTO、配置文件、空壳 Controller 和纯样式文件。
- 保持源码片段逻辑完整，避免在类、函数或结构块中间硬截断。
- 对材料执行重复率、调试残留、结构闭合、页数饱满度和名称版本一致性检查。
- 提取完成后运行 `scripts/audit_common_identifiers.py`，报告常见架构词、实现词、UI 词和泛化业务词的频次（包括 CamelCase、snake_case 拆分结果），用于识别通用代码和源码选材风险。

## 禁止事项

- 不得注入无关算法、无关类或伪造代码来降低重复率。
- 不得重复填充源码凑页数。
- 不得把通用框架代码包装成核心创新。
- 不得删除关键上下文导致代码不可解释。
- 不得把多个独立软件、无关后台、公共网关或其他项目代码混入同一源程序鉴别材料。
- 不得隐瞒开源、委托、合作等可能影响材料说明的事实。
- 允许在申请人明确授权的商业秘密保护场景下，使用 `scripts/pseudonymize_common_identifiers.py` 对选定的内部通用标识符做可追溯、等长、语义保持的保密化处理；替换名应与业务有明确关联但不采用行业通用词，不得使用无意义随机串。必须跳过注释、字符串、页眉、软件名称和公开框架 API，保留映射在 `work/`，并记录保密化前后的审计结果。不得把该处理用于降低重复率或伪造原创性，不得将映射 JSON 放入 `deliverables/vN/`。

## 验收要求

- 源码材料能追溯到真实路径。
- 审计报告包含重复率、重复行 Top 列表、调试残留、闭合完整性、行数饱满度和整改建议。
- 风险项无法自动关闭时，必须列入人工确认项。
- 本地重复率和通用标识符报告只反映材料内部结构与词频，不连接外部登记机构或第三方代码库，不能保证外部查重通过；最终原创性、开源/第三方使用和提交口径必须由申请人据实确认。
- 标识符保密化只能降低命名泄漏，不能阻止代码逻辑被反编译或复制；商业秘密保护还必须依靠源码范围选择、敏感文件/密钥/内部地址/客户数据排除和访问控制。
