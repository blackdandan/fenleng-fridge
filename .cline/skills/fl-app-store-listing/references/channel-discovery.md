# 渠道发现与可上架判断

核验日期：2026-10-15。用于“以前记录过哪些市场”“继续上架能上的商店”等未指定市场的请求。

先读消费项目的渠道清单、账号状态、实际应用和发布记录；Owner 最新状态优先于旧草稿。按“市场 × 平台 × 地区 × 主体类型”建立推进表，分开记录可注册、实名认证通过、具有应用分发权限、资料齐备、平台已保存、已提交、审核通过和公开上架。账号通过认证不是产品通过审核。

优先推进已有可用账号和对应正式产物的渠道，再核验尚未注册的候选；不能把以下平台入口当作当前项目准入承诺：

| 候选 | 官方入口/证据 | 需要核验的差异 |
| --- | --- | --- |
| vivo 中国站 | [文档中心](https://dev.vivo.com.cn/documentCenter/doc/52) | 账号主体、名称/软著、Android APK；不要误用海外站规则 |
| 华为 | [Android 分发入口](https://developer.huawei.com/consumer/cn/appgallery/)、[HarmonyOS 分发](https://developer.huawei.com/consumer/cn/appgallery/devstart/) | Android 与 HarmonyOS 应用记录、包型、签名和能力分别核验 |
| 荣耀 | [实名认证权益](https://developer.honor.com/cn/doc/guides/100619) | 当前个人应用管理仅限 Web；无 APK 权限时停止建 APK 提交草稿 |
| 小米 | [开发者账号注册标准](https://dev.mi.com/distribute/doc/details?pId=1731)、[暂不收录类型](https://dev.mi.com/distribute/doc/details?pId=1354) | 当前不接受个人开发者申请，个人身份发布 APP 属不收录类型；个体户需核对实际组织类型，不推断属于普通企业 |
| OPPO | [软件商店接入入口](https://open.oppomobile.com/newservice/capability?pagename=app_store) | 核验当前个人/个体户/企业分发权限；当前个人认证页允许普通应用、暂不支持游戏，仍需实名认证及产品资格；广告开户资格不等于准入 |

其他渠道仅在项目已有记录或 Owner 要求扩展时继续核验官方接入、当前是否接受新应用、主体和地区。无法读取的登录页、仅搜索摘要或历史论坛答复标为待核验，不得补造准入结论。

确认实际推进市场后再创建其资料目录；受阻渠道保留证据、原因和解除条件即可。不要生成所有市场空目录，也不要自动注册新主体、购买账号或接受合同。共用经营主体资料从基座 organization 入口读取，应用事实留在消费项目。

## 荣耀应用分发资格与后续 APK 提交

核验日期：2026-10-15。官方[实名认证权益](https://developer.honor.com/cn/doc/guides/100619)、[创建应用](https://developer.honor.com/cn/doc/guides/100882)、[发布 APK](https://developer.honor.com/cn/doc/guides/100884)。

先检查实际账号权限。当前实名认证说明中个人账号的应用管理仅限 Web 应用，企业/组织享有全平台服务；所以“个人审核通过”不能证明有 APK 发布资格。消费项目历史个体户被拒或改申请个人时，应保存该事实和当前权限证据，不重复申请，也不擅自注册企业、变更法律主体或借用账号。无实际 APK 权限就记录为受阻，不生成假可提交资料。

权限确认可用后，创建应用前检查包名、支持设备和一级分类；官方说明一级分类不可修改。手机 APK 和手表 HAP 不是同一包位。进入管理中心 > 生态服务 > 应用服务 > 应用分发，填应用基本信息和版本，上传后必须选取软件包；检查地区、内容分级、隐私、版权、备案与审核账号。

应用内付费不自动等于联运；官方发布文档允许有内购的非联运应用选择非联运，按真实合作关系填写，不因付费勾选联运或签新合同。当前表单需要版权证书时核验原件格式/大小和授权关系；不能用别市场授权函直接充当荣耀授权。

Owner 已授权提交且资料齐备时完成提交确认并保存平台状态。只有页面已提交、审核通过、已上架各阶段的对应证据才能标记状态，不能把保存成功当作上架。

## OPPO账号现场核验

2026-10-15的已登录管理中心 `/new/admin/qualification` 与个人实名认证页明确说明：个人账号暂不支持游戏，支持普通应用等。因此不能依据早年论坛“个人不能上传Android应用”拒绝当前普通应用。先读取认证状态与退回原因；本轮实际缺项是本人手持身份证人像面的彩色高清照片，涉及本人实名和可能的人脸识别，按宿主授权规则处理，不自动从历史附件挑选并对外提交。

账号完成认证后，再核对应用的版权权利人、APP备案运营主体是否符合个人发布要求；个人账号可发布普通应用不能推导为接受其他主体备案或他人软著授权。保留主体选择，认证页提示归属主体认证后不可改时，不为绕过审核自行切换或重建账号。
