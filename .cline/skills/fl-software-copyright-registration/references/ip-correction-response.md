# Correction Response Rule

## 适用场景

当用户收到软件著作权补正通知，并需要诊断原因、整改材料或生成补正说明时，必须遵守本规则。

## 核心原则

补正回复必须逐条对应退回意见，解释真实原因，说明已采取的整改动作，并列明重新提交材料。不得虚构事实或用模板化承诺掩盖材料缺陷。

## 必须执行

- 保留补正通知原文或用户摘要。
- 将每条退回意见映射到具体材料和具体缺陷。
- 区分事实说明、整改动作、重新提交材料和人工承诺。
- 对源码雷同、材料缺失、名称版本不一致、签章问题、说明书不足等问题分别处理。
- 补正说明中的软件名称、版本、申请主体必须与其他材料一致。

## 禁止事项

- 不得编造主管机构未提出的退回原因。
- 不得承诺不存在的独立开发事实。
- 不得建议隐藏第三方代码、开源代码或其他依法、依通知需披露的事实。
- 不得用无关代码替换、注入或重复填充作为补正策略。

## 验收要求

- 补正诊断报告包含退回意见、原因判断、整改动作、待重交材料和人工确认项。
- 补正说明能被追溯到真实整改动作。
- 所有无法确认的事实必须留给用户人工确认。
