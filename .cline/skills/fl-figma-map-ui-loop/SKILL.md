# fl-figma-map-ui-loop

以 `figma-map.md` 将 Figma 节点、行为 spec、Flutter widget、页面状态和验收证据绑定起来，持续推进设计稿驱动的 UI 实现。

## 适用边界

- 用户要求在 Flutter 项目中按 Figma 设计稿实现、还原、补全或排查页面、卡片、组件和状态时使用。
- 本 Skill 负责设计节点到代码的实施循环与视觉保真门禁；Fenleng Token、主题、组件和可访问性规则由 `fl-ui-design-system` 提供，业务行为仍以项目 spec 为准。
- 纯后端、纯业务逻辑、非 Flutter UI，以及没有设计稿依据的开放式视觉设计不使用本 Skill。
- 项目特有的构建、热重载、原生集成、导航和尺寸适配约束应从项目指导文件和文档读取，不写回本 Skill。

## 输入

- Figma 文件或可精确读取的 node-id；
- 项目行为 spec、目标 Flutter 工程和待实现范围；
- 已有或待创建的 `docs/figma-map.md`；
- 项目的设计基准宽、尺寸适配约定、构建与设备入口；
- 可用的 Figma MCP，以及按验收路径需要的 Flutter、Python/Pillow、ADB 和 Dart 环境。

## 输出

- 按已确认范围实现的 Flutter 页面、卡片、组件或状态；
- 更新后的 `figma-map.md`、页面明细、共享组件清单和阻塞清单；
- Figma 与渲染结果逐块对比的数字证据；
- 独立报告的 golden 回归、真机复核和非基准宽检查结果；
- 尚未验证、需要人类决策或依赖外部团队的明确事项。

## 执行步骤

1. 读取项目指导文件、行为 spec、现有 UI 骨架和同类组件；若项目使用 Fenleng Design System，同时加载 `fl-ui-design-system` 所要求的 Project Knowledge。
2. 检查依赖：Flutter 与 Figma MCP 是实现路径的基础；保真采样需要 Python 3 和 Pillow；真机循环需要 ADB；VM Service 路由直跳需要 Dart。缺失的路径必须在结果中标为“未做数字门禁”，不得默认通过。
3. 建立或读取映射清单。若缺少 `docs/figma-map.md`，复制 `assets/figma-map-template.md` 并按“页面索引、共享组件、backlog、页面明细”分层填写。
4. 在首次实现前与用户确认一次范围、优先级、可疑 node-id、尺寸适配 API、设计基准宽、适配量类型，以及外层是否已统一适配。范围与适配未确认时不得进入自治实施循环。
5. 将已确认的待做行登记到当前宿主的任务列表，从最高优先级 `⬜` 行开始逐行执行：读 spec、按 node-id 取 Figma、复用现有骨架、实现 widget、验收、回填状态。
6. 每行完成前执行“覆盖驱动验收”：枚举当前准节点的顶层子节点；逐块测背景、文字、图标或插图的颜色、尺寸和位置；反向检查渲染中是否多画、重复或错套容器；所有适用块都有数字证据后才可标记 `✅`。
7. 保真采样通过后再更新 golden，并在真机或模拟器上复核实际资源、字体和原生视图。存在尺寸适配层时，再用明显不同于基准宽的宽度检查一次，避免漏适配或双重缩放。
8. 回填 `figma-map.md`、当前页面明细和任务状态，然后继续下一行。只有遇到原生与 Flutter 选型不明、spec 真缺口，或需要 commit/push/PR 等外发动作时才暂停请求用户决定。

## 阶段 0：建图与范围确认

每个 UI 模块维护一张瘦索引，惯例结构如下：

```text
docs/
├── figma-map.md
├── components.md
├── backlog.md
└── pages/<name>.md
```

- 一行代表一个可独立实现和验收的交付物，不等于一个 Figma 节点。
- 不同行为或状态需要独立代码分支和验收时拆行；同一交付物的多张参考图放在同一行并标记“当前准”。
- 卡内 tab 属于同一 widget 时不拆行，在内容区登记 tab 到 node-id 的映射。
- 状态使用 `✅` 完成、`🔶` 进行中、`⬜` 待做、`⏳` 整页占位；缺 node-id 使用 `TODO` 并进入 backlog。
- 推进类型默认 `🤖`。仅选型、spec 决策和外发动作标为 `🧑`；缺 node-id、缺原生 factory、外部依赖属于阻塞，不属于人工推进类型。
- 新增或删除页面只改索引；单页细节写入 `pages/`；跨页复用组件写入 `components.md`；阻塞解锁后从 `backlog.md` 删除，不保留历史流水账。

尺寸适配必须在第一个尺寸落代码前明确：适配 API、设计基准宽、字号/间距/圆角/边框/图片分别如何适配，以及外层是否已包裹适配容器。基准宽下缩放因子通常为 1，golden 和保真采样都无法发现漏适配或双重适配，因此非基准宽复核是独立门禁。

## 阶段 1：逐行自治循环

每个已确认行按以下顺序推进：

1. 读取行为 spec，明确字段、边界、交互和状态联动。
2. 使用精确 node-id 获取节点结构和截图，视觉以 Figma 为准，行为以 spec 为准。
3. 优先复用项目已有卡壳、tab、表头、全屏入口和主题能力；不要根据文字描述重造已有范式。
4. 实现目标状态并建立可重复到达该状态的入口。
5. 对照 Figma 执行数字化保真采样。
6. 保真通过后更新并运行 golden 回归，再做真机复核和必要的非基准宽复核。
7. 记录证据、回填 `✅`，继续下一行。

自治意味着在同一任务内尽量连续推进已确认的自动行，不意味着跳过用户的范围确认、外发授权或真实阻塞。

## Figma 节点读取约束

- 大文件只按精确 node-id 读取结构和截图；不要依赖整页搜索、当前选区或整文件截图。
- 一个父锚点足以开始时，读取其节点树并按子节点名称识别状态变体，不反复向用户索要每个子节点 id。
- 截图先保存到仓库内临时文件再检查，用完后移除临时文件。
- Figma 连接是单通道时必须串行读取，避免并发请求互相挤占而超时。
- 插件断连、设备断连或构建失败属于异常暂停；修复或明确等待，不得把未运行的检查视为通过。

## 保真验收门禁

“对齐 Figma”必须逐块给出数字，而不是只做肉眼判断。使用 `assets/fidelity_sample.py` 对 Figma 截图和同态渲染截图采样：

- `bg FIG REN`：背景网格、平整度、色相和最大通道差；
- `point IMG XF YF`：关键颜色 token 的 hex；
- `glyph IMG X0 Y0 X1 Y1`：文字 cap 高与估算字号；
- `bbox IMG X0 Y0 X1 Y1 HUE`：图标、插图或色块的包围盒与位置比例；
- `sxs FIG REN Y0 Y1`：生成并排图作为人工复核兜底。

每行验收遵循四条规则：

1. 用当前准节点的直接子节点生成覆盖清单，背景层始终算一块。
2. 逐块选择对应采样：背景核层次和色相，文字核颜色和字号，图标/插图核大小、位置与叠放。
3. 反向检查渲染是否存在 Figma 没有的重复元素、多余装饰、错误白卡或错误裁切。
4. 每个适用块给出 `✓/✗` 和数字；有一块未核就不能标记完成。

既有页面也视为未验证。golden 只证明“当前输出相对历史基准没有变化”，不证明“当前输出符合 Figma”，两种结论必须分开报告。

## Golden、真机与原生视图

- 先做 Figma 保真采样，再运行 `flutter test --update-goldens` 固化基准。模板见 `assets/golden_test_template.dart`。
- golden 在设计基准宽、`devicePixelRatio=1.0` 下运行；含适配层时额外检查 320 或 430 等非基准宽。
- golden harness 可能掩盖 Material 祖先、中文字体、emoji、图片资源和包资源路径问题，因此最终至少做一次真机或模拟器复核。
- PlatformView 的内容由原生侧渲染时，只验证非空、槽位、尺寸和位置；内容明显不符时写入页面文档或 backlog，交原生侧处理，不把 Flutter 外壳任务误判为失败。
- 可为调试构建注册 VM Service 路由扩展，并用 `assets/vm_goto.dart` 稳定跳转目标页。扩展必须以 `kDebugMode` 守卫，调用前等待应用进入可导航状态。

## 可复用实现范式

- 纯原生：Flutter 外壳内整块 PlatformView；
- 混合：部分 tab 使用 PlatformView，部分 tab 使用 Flutter；
- 纯 Flutter：全部由 Flutter widget 渲染。

优先复用卡壳、全屏入口、可注入 body 的泛型 tab 卡、集中色板和文本样式。原生 body 常需要 `ClipRect` 与顶部对齐裁切；固定高度卡片应确保 body 落在可见区域；窄屏文本使用弹性布局、单行省略或按需缩放，避免 RenderFlex 溢出。

## 成功标准

- 已确认范围内的每个交付物都能由 `figma-map.md` 追踪到 node-id、spec、实现和状态；
- 每个 `✅` 行都具有顶层区块覆盖清单和适用的颜色、字号、尺寸、位置数字证据；
- Figma 保真、golden 回归、真机复核和非基准宽复核分别报告，没有互相替代；
- 项目既有组件、Fenleng Token 和尺寸适配约定得到复用；
- 未完成项准确进入 backlog 或用户决策清单，没有把缺失依赖默认为通过。

## 失败处理

- 缺 node-id、原生 factory 或外部依赖：登记到 `backlog.md`，继续其他已确认且可执行的行。
- Figma MCP 断连、设备断连或构建失败：暂停受影响路径，报告具体错误和已完成证据；恢复后从当前行继续。
- 无 Python/Pillow：不得声称通过数字保真门禁；可以继续实现，但结果必须标记未完成保真验证。
- spec 与 Figma 冲突：行为遵循 spec、视觉遵循 Figma；无法同时满足时列出冲突并请求用户决策。
- 原生与 Flutter 选型不明、spec 真缺口或需要外发：停止该决策点，不替用户猜测或扩大授权。
- 任一顶层区块缺少证据、采样失败或真机未复核：保持 `🔶`，不得标记 `✅`。
