# UI 视觉审查清单

## 结构

- 首屏能否理解页面目的；
- 主操作是否唯一、清晰且可发现；
- 标题、正文、辅助信息和状态层级是否稳定；
- 是否存在不必要的装饰、重复信息或过深层级。

## 状态

- 默认、加载、空、错误、成功、禁用和权限不足状态是否覆盖；
- 失败是否有可理解的原因和恢复路径；
- 操作反馈是否接近触发位置；
- 主题切换后是否仍然可读。

## 规范

- 颜色、间距、圆角、字体和动效是否来自 Token；
- 是否复用了组件目录中的组件；
- 是否出现页面私有视觉体系；
- 是否违反端侧 UI 工程规则。

## 可访问性

- 状态是否不只依赖颜色；
- 文本和交互控件是否具备足够对比度和可识别性；
- 触控、键盘或辅助技术是否有合理路径；
- 文本放大、窄屏和长内容是否可用。

## 输出

审查结果必须区分 `pass`、`needs-change` 和 `humanDecisionRequired`，并给出具体页面、组件、Token 或状态证据。
