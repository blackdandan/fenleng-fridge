# 中国渠道 APP Day 0 首次启动隐私同意契约

本契约适用于所有包含 `china` 发布渠道的 Android/iOS/HarmonyOS NEXT APP。它是工程初始化和发布验收条件，不得推迟到上架前补做；`global` 渠道继续遵守目标地区的独立合规契约，不根据运行时地理位置猜测渠道。首次启动协议门禁是中国渠道专属能力，海外版不得复用或短暂渲染该门禁。

## 1. 依据与 Fenleng 产品策略

1. 四部门《App违法违规收集使用个人信息行为认定方法》要求 App 首次运行时以弹窗等显著方式提示用户阅读隐私政策等收集使用规则，并将“征得用户同意前就开始收集个人信息或打开可收集个人信息的权限”列为违规情形。
2. 《中华人民共和国个人信息保护法》第 13 至 15 条要求个人信息处理具备合法性基础；基于同意处理时，同意必须在充分知情前提下自愿、明确作出，并提供便捷的撤回方式。
3. Fenleng 的中国渠道产品策略要求首次启动同时提供《隐私政策》和《用户协议》的可读入口并取得一次明确同意。“用户协议同屏确认”是 Fenleng Day 0 产品契约，不冒充监管原文。

## 2. 首次启动门禁

1. `china` 构建首次启动必须先显示显著、不可被业务页面遮挡的同意门禁；不得以默认勾选、继续使用即同意、倒计时自动同意或关闭弹窗等方式代替明确点击。
2. 两份文件必须分别提供可聚焦、可点击的《隐私政策》和《用户协议》入口；同意前使用随包离线文本阅读，不通过 HTTP、WebView 或外部浏览器加载。
3. 主操作使用明确的“同意并继续”等文案；必须提供“暂不同意”等次操作。暂不同意后保持在无 SDK、无业务数据处理的阻断状态，可继续离线阅读并重新选择，不得频繁弹窗干扰。
4. 当前政策版本已同意时可以直接进入后续初始化；同意记录缺失、损坏或渠道不匹配时 fail closed，重新显示门禁。
5. 个人信息处理目的、方式或种类发生实质变化时提升稳定的 `policyVersion`，重新取得同意；仅改错别字不得滥用重新同意。

### 2.1 `global` 首屏硬边界

1. `global` 构建在全新安装、清空数据或升级后的第一个可见帧，均不得显示或闪现要求同意《用户协议》《隐私政策》的弹窗、整页门禁、底部面板、勾选框或横幅。
2. 海外版异步初始化期间只能显示不含协议同意操作的中性启动画面；不得先构建中国门禁再异步跳过，避免慢设备或首启编译时出现协议闪屏。
3. 海外版仍须在设置、账号页、登录页法律链接或目标市场要求的位置提供可访问的用户协议和隐私政策，但查阅入口不得变成使用 App 前的强制同意门禁。
4. 该分流只接受编译期 `china` / `global` 渠道，不得根据设备语言、IP、SIM、系统地区、商店地区或运行时定位改变首屏行为。
5. 产品自动化必须在首次 `pump` / 首帧就断言 `global` 不存在协议标题、隐私标题、同意按钮和法律入口；等待初始化完成后的断言不能替代首帧断言。`china` 首启门禁测试必须同时保留。

## 3. 同意前唯一 allowlist

同意前仅允许：

- 操作系统、Flutter engine / Widgets binding 与绘制门禁所需的纯 UI Theme；
- 读取本应用自己的同意记录：是否同意、政策版本、渠道和同意时间；
- 读取安装包内的离线《隐私政策》《用户协议》；
- 读取无障碍文字缩放、亮暗模式、安全区和本地化渲染所必需的系统显示状态。

除此之外默认禁止。allowlist 必须在项目资产中显式声明，不得用“基础能力”“必要 SDK”等模糊词扩大。

## 4. 同意前禁止项

1. 任何第一方或第三方业务 SDK 均不得构造、配置、激活或由原生入口自动初始化，包括但不限于统一客户端、认证、微信、Firebase、推送、Telemetry、崩溃、广告、地图、分享、支付和远端配置。
2. 不得发起网络请求、DNS 解析、WebView 页面加载、埋点、日志上报、崩溃上报或设备注册。
3. 不得申请权限，或读取设备标识、剪贴板、相册、通讯录、短信、定位、相机、麦克风与存储内容。
4. 不得恢复登录、读取账号缓存、业务数据库、业务文件、搜索历史、提示内容或生成新的业务/设备标识。
5. Dart 层延迟初始化但 Android `ContentProvider`/`Application`、iOS `AppDelegate`/静态 initializer 或 Flutter plugin 注册时已经启动 SDK，仍视为不合格。项目必须从 Day 0 在 Android `MainActivity`、iOS `AppDelegate`、HarmonyOS `EntryAbility` 采用 **`DeferredPluginRegistrant`（延后插件注册模式）**：冷启动阶段禁止直接对文件选择（如 `file_selector`）、微信、支付、第三方身份等插件执行 `GeneratedPluginRegistrant` 全量自动注册，必须将非 allowlist 原生插件注册绑定到 `post-consent bootstrap` MethodChannel/Bridge 回调中，待用户点击“同意并继续”并持久化成功后才完成原生插件挂载，并审计原生 manifest、plist、生成的 plugin registrant 与最终产物合并结果。

## 5. 同意记录与后续初始化

1. 同意记录使用操作系统本地键值能力或等价的最小自有 Adapter；不得为了读取门禁本身先初始化业务存储 SDK。
2. 用户点击同意后，先原子持久化 `policyVersion`、`releaseChannel` 和 `acceptedAt`，成功后才进入 post-consent bootstrap；持久化失败保持阻断并给出可重试错误。
3. post-consent bootstrap 必须有明确入口、幂等保护和 `loading`、`error`、`retry` 状态；重复点击、页面重建或生命周期恢复不得重复初始化 SDK。
4. 用户撤回同意时停止后续可停止的数据处理并执行具体产品声明的重启/退出边界；下次启动重新显示门禁。撤回不能伪造成只关闭分析开关。

## 6. 项目资产与测试

`00-context/project.yaml` 至少声明：

```yaml
privacyConsent:
  releaseChannels: [china]
  policyVersion: ""
  consentRecordPath: ""
  offlineTermsPath: ""
  offlinePrivacyPath: ""
  preConsentAllowlist:
    - "flutter-rendering"
    - "consent-record"
    - "bundled-legal-documents"
    - "accessibility-display-state"
  postConsentBootstrapPath: ""
```

自动化和真机验收必须覆盖：首次默认、分别阅读两份文本、暂不同意、同意后单次初始化、持久化失败、初始化失败与重试、已同意直达、政策版本升级重新同意、`global` 首帧无门禁及初始化完成后仍无门禁、浅色/深色、大字、窄屏和长中文。静态测试不能替代最终包的冷启动抓包、权限日志、原生自动注册审计和应用市场隐私检测。

## 7. 中国渠道运行期敏感权限说明

1. 首启同意不是后续敏感权限的概括授权。相机、相册、定位、麦克风、通讯录、短信和存储等权限只能在用户主动触发具体功能时按需申请，不得在启动阶段批量索权。
2. `china` 渠道在调用系统权限弹窗前，必须用当前 App 的 Fenleng Design System dialog 或 bottom sheet 同步说明：申请的权限、对应功能、将访问的数据、明确用途、拒绝后的功能影响，以及“继续”和“取消”操作；取消不得触发系统权限请求。
3. 已授权时可直接执行功能；已拒绝时提供可理解的降级路径；永久拒绝时可由用户主动打开系统设置。页面销毁、重复点击或并发请求不得重复弹系统权限。
4. `global` 渠道按目标市场与平台标准契约执行，不展示中国渠道专用说明；渠道必须由构建配置显式传入，不得依据 IP、SIM、语言或地理位置猜测。
5. Flutter 项目应通过 `fenleng_sdk_flutter_china_permissions`（或 Experience Manifest 指定的后继官方能力）编排，不得在业务 Widget 中散落 `Permission.request()`。底层复用成熟的平台权限插件，不重复实现原生权限桥。
6. 每个 App 必须显式登记实际权限目录：稳定功能 ID、权限、用途、数据范围、拒绝影响和政策入口。未登记目的时 fail closed，不发起系统申请。

自动化验收至少覆盖：已授权、首次说明后允许、说明页取消、系统拒绝、永久拒绝与设置入口、并发去重、页面销毁、`china`/`global` 分流，以及“说明在系统请求之前发生”的顺序断言。
