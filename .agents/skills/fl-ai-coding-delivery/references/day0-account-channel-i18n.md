# APP / Web Day 0 账号、渠道与国际化契约

本契约适用于从零创建或首次完善 Fenleng APP、Web 前台及其共享账号能力。它是工程初始化条件，不得推迟到上架前补做。第 3 节的语言要求也适用于其他直接面向用户的 FL 界面，不以是否含账号为前提。

## 1. 账号注册与邮箱验证

1. 邮箱注册必须先发送验证码并验证成功，再原子化创建账号和登录会话；未验证邮箱不得落为正式账号。
2. 验证码接口使用通用响应，具备发送、校验、过期、频率限制和重复提交测试；客户端不得把“请求已受理”误呈现为“邮件一定已发送”。
3. 登录、注册和账号生命周期优先使用 Fenleng Client SDK 的当前公开契约，不在各产品内复制共享平台协议。

## 2. 注销从首版可用

1. 支持注册的产品从首版就在账号设置内提供可发现的“注销账号”按钮，不得依赖客服或后续版本补充。
2. 注销申请提交后进入 7 天等待期；7 天内再次成功登录即取消注销并恢复正常状态，7 天内不得物理删除账号。
3. 等待期届满且期间没有成功登录时，才执行共享平台定义的数据删除/匿名化；界面必须明确申请时间、预计执行时间及登录可撤销规则。
4. 覆盖申请、重复申请、等待期登录撤销、到期执行和执行后的认证失败测试。

## 2.1 Apple 平台登录从首版可用

1. 面向 iOS、iPadOS、macOS 或 tvOS 分发的应用，只要提供微信、Google、Facebook 等任一第三方或社交登录，Day 0 必须同时提供 Sign in with Apple；Apple 登录入口与其他第三方登录保持同等级、同可发现性，不得藏入二级页面或仅在审核构建临时开启。
2. Apple 登录只请求业务必需的姓名和邮箱，必须接受 Apple 私密转发邮箱，不得要求用户改填真实邮箱才能完成账号创建；未经同意不得把登录或应用交互用于广告画像。
3. China 渠道使用 Apple 原生授权，由 Fenleng Shared Platform 直接验证 Apple identity token，登录链路不得依赖 Firebase 或 Google 服务；Global 渠道默认由每产品独立 Firebase 项目完成 Apple Provider 身份认证，再经 Fenleng Client SDK 与 Fenleng Shared Platform 换取统一 Session。两条路径按构建渠道注入，使用独立客户端登记，Apple 直验登记不得要求 Firebase projectId。必须使用已批准的共享身份契约；业务应用不得建立第二套账号库、私自信任未经服务端校验的 Apple 凭据或把 Provider Token 当作 Fenleng Session。
4. Apple App ID 的 Sign in with Apple Capability、应用 entitlement、正式 Bundle ID、Apple Team ID、App Store Provisioning Profile、Firebase/Provider 配置和服务端 audience 必须一致。缺少任何正式配置时 fail closed，不得使用占位值冒充接入完成。
5. 客户端必须覆盖成功、用户取消、凭据撤销、能力不可用、网络超时和服务端拒绝；所有分支必须结束 loading、允许重试，并使用本地化可理解提示，不得直接展示 SDK/平台原始异常。
6. 声明支持 iPad 的应用必须在 iPhone 与 iPad 上分别验证全新安装和覆盖升级；第三方 Provider 未安装或不可用时，点击入口也必须立即给出反馈，不能表现为无动作。

## 3. 国际化从首版建立

1. APP 与 Web 分别建立标准字符串目录；业务界面禁止散落硬编码的用户可见字符串。
2. Day 0 至少提供二十种有实际译文、可切换的界面语言。首批统一集合为 `zh-CN`、`zh-TW`、`en`、`es`、`fr`、`de`、`pt-BR`、`it`、`ja`、`ko`、`ar`、`hi`、`id`、`ru`、`tr`、`vi`、`th`、`nl`、`pl`、`uk`；中文简体与繁体分别计数。端侧可按平台标准映射为等价 locale，但不得减少语言或仅声明支持而让主要界面回退中英文。
3. 首次语言按设备/浏览器语言解析，用户可在产品内显式选择；显式选择持久化并优先于设备/浏览器语言。语言标签使用该语言的自称，并提供回到系统语言的选项。
4. 未命中语言及缺失键使用明确且可预测的默认语言回退；缺失键必须可检测，不能以回退掩盖未翻译的主要界面。资源支持变量、复数、日期/数字格式化；阿拉伯语等 RTL 语言遵循端侧布局方向，产品名等必要专有名词可保留原文。
5. 至少验收二十语言的资源完整性、首次解析、用户切换、重启/刷新持久化、缺失键、变量/复数、长文本布局及 RTL。注册/登录、主要导航、错误提示、设置和核心业务流程不允许缺失目标语言译文。无直接界面的服务端或 SDK 不强制翻译内部日志，但交给界面展示的错误需提供可本地化的稳定 code/key，不把原始异常当成用户文案。

## 4. 中国与全球渠道隔离

1. 构建配置必须显式选择 `china` 或 `global`，不得用运行时地理位置猜测渠道，也不得让一个构建同时暴露两套合规入口。
2. `china`：注册/登录前以未默认勾选的显式勾选框确认用户协议与隐私政策；提供中文及产品声明的其他语言；接入微信登录；在游客和登录态可访问的显著位置展示可点击的 APP备案号与工信部查询入口。
3. `global`：使用 Firebase 统一认证入口；Apple 平台构建按第 2.1 节启用 Sign in with Apple；不展示中国 APP 备案号或备案查询入口；隐私与协议仍按目标地区合规要求提供，但全新安装的首屏及异步启动帧不得显示、闪现或强制通过用户协议/隐私政策同意门禁。法律文本应在设置、账号、登录页法律链接或目标市场要求的位置保持可访问。
4. 渠道差异只通过编译期 flavor/environment 配置和依赖注入实现；业务页面不得散落国家判断。不得根据语言、IP、SIM、系统地区或商店地区推断渠道。CI 对每个渠道分别编译并验证专属入口存在、另一渠道入口不存在，并在 `global` 首帧断言协议同意门禁从未被渲染。
5. Firebase 配置归属于具体产品，不得跨项目共用一份 `projectId`、App ID 或客户端配置。新项目 Day 0 先提供带产品稳定前缀的显式占位配置，默认 `enabled=false`；启用时若仍为空或为占位值必须 fail closed。占位配置不得冒充真实接入完成，也不得包含服务端私钥。

## 5. 交付证据

- 工程文档记录字符串目录、语言解析器、用户偏好存储、渠道配置、每项目独立 Firebase 配置、认证适配器和注销入口的真实路径。
- 测试或静态 Guard 能证明首版包含邮箱验证、7 天注销、Apple 登录适用性门禁、i18n 与双渠道隔离；缺少任一项时不得宣称 Day 0 完成。
