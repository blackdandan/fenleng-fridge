# Day 0 iPad 基础适配契约

## 适用范围

面向 iOS/iPadOS 的 App，Day 0 默认同时支持 iPhone 与 iPad 基础适配。新建、首次完善及相关界面修改必须读取并验收本契约，不以账号或第三方登录为前提。Owner 明确批准的仅手机产品例外必须记录理由；AI 不得自行排除 iPad。

## 设备与布局

- Flutter iOS 各构建配置使用 `TARGETED_DEVICE_FAMILY = "1,2"`，最终发布包复核 `UIDeviceFamily` 包含 1 和 2。不得把 iPhone 兼容窗口当作 iPad 原生适配证据。
- 按可用逻辑宽度及 Fenleng Design System 断点响应式布局，不依赖设备型号。手机布局不得退化；平板表单居中限宽，列表保持可读宽度，背景覆盖屏幕并正确处理安全区，导航与抽屉可发现且不过度拉伸。
- 宽度策略维护在共享 UI 边界，使用语义 Token 和已有组件；不得复制业务状态，不强制所有产品采用同一具体宽度值。
- 默认支持 iPad 横竖屏、系统安全区、软键盘与可滚动表单。弹窗、底部操作和关键按钮不得被遮挡；保持主题、国际化、长文本、RTL 与系统大字体能力，不通过缩小字号规避溢出。
- 基础适配不强制复杂分栏、常驻侧栏、多窗口或指针交互；宽屏响应式表中的侧栏策略是可选增强，不是 Day 0 分栏门禁。

## 验收与交付

- 覆盖手机与平板纵横屏、系统大字体、软键盘、加载/空/错误状态以及核心路径，补相称布局测试、截图和真实运行证据。第三方客户端未安装时，必须给出本地化可理解反馈并结束 loading。
- 支持设备与 App Store 原生 iPad 商店截图需求必须记录在产品上架资料；调试截图只能作为测试证据，不能冒充正式商店截图。
- 模拟器 SDK 架构限制如实标记 `not-run`，记录未验证设备/系统、原因和后续验证条件；不得移除真实功能绕过，不得把旧系统模拟器冒充最新 iPadOS 真机验收。
- 设备支持变更后生成新构建号的发布包，不能继续上传旧候选包；复用项目既有上传通道，不在本契约中建设新通道。

设计规范来源：Fenleng Design System 的 layout、text-scale-contract、accessibility 与 component-catalog；产品只选择符合自身内容的限宽与导航策略，不新增品牌 Token。
