# Day 0 产品埋点契约

本契约适用于所有新建或首次完善的 Fenleng APP、Web 与小程序。埋点是功能交付的一部分，不得等上线后补做。

## 1. 统一入口

1. 端侧必须使用 Fenleng Client SDK 的统一 telemetry API，不得在产品内自建 HTTP 上报、日志转埋点或第二采集通道。
2. 项目必须声明事件目录真实路径、用户同意来源以及 `platform`、`appVersion`、`buildNumber`、`releaseChannel`、`locale` 公共上下文来源。
3. Application 身份只由共享平台认证上下文决定；客户端不得提交或覆盖产品 ID。

## 2. 功能交付同步要求

1. 每个可观察的关键流程在实现时同时定义最少必要事件：进入、关键提交、成功和有决策价值的失败；漏斗步骤使用稳定的版本化事件名，例如 `account.registration.completed.v1`。
2. Coding Spec 必须列出新增/变更事件、触发时机、属性白名单、同意分类和验证方法；没有必要事件时必须写明理由。
3. 代码验收同时验证事件只触发一次、结果准确、未知事件失败关闭、无同意不采集、退出登录或撤回同意清空未发送队列。

## 3. 隐私和可靠性

1. 禁止上报密码、Token、验证码、邮箱、完整内容正文、认证头、支付凭证及未获同意的个人信息；敏感键必须拒绝，不得仅用字符串替换后继续上传。
2. 单批最多 50 条，队列有明确上限；只在服务端确认接收后移除。失败可通过 SDK 的幂等重试恢复，不能无限重试或阻塞主流程。
3. APP 在进入后台、Web 在页面隐藏以及小程序离开时尝试短时 flush；失败事件保留在受控队列，超出上限丢弃最旧非安全事件。

## 4. 交付证据

- 项目文档记录事件目录、SDK 初始化、同意状态、公共上下文和关键流程埋点的真实路径。
- CI 或单元测试覆盖至少一个成功事件、一个失败事件、敏感字段拒绝和撤回同意。
- 缺少 SDK 接入、事件目录或同意门禁时，不得宣称 Day 0 或对应功能完成。
