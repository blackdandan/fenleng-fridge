# Mocking & Testing Rules (测试与 Mock 规约)

本规则用于约束 Agent 编写单元测试的行为，确保测试的真实有效性并实现执行环境隔离。

---

## 1. 测试隔离与 Mocking 规范

1. **强环境隔离**：单元测试必须是纯粹的、无副作用的本地测试。严禁在测试中发起真实的外部网络请求或连接真实数据库。
2. **测试替身 (Test Double) 选用**：
   * 优先使用轻量级 Mock 框架（如 Mockito、MockK）模拟外部组件。
   * 涉及数据库操作，必须使用内存数据库（In-memory DB）或 Repository Mock 桩，严禁依赖真机环境。
   * **值对象与实体 (Entities & Value Objects)**：对于纯数据载体、领域实体或值对象，必须直接使用真实对象，**严禁 Mock 实体类**（以保持 Context 极简化，避免无谓的代码开销）。

---

## 2. 断言强度与卡点 (Assertion Standards)

1. **禁止编写无断言测试 (No Empty Assertions)**：
   * 编写的测试方法必须包含实质性的断言校验（如 `assertEquals`、`verify`）。
   * 严禁仅编写“执行即通过”的作弊用例（即只调用方法而无结果比对，仅为了刷覆盖率）。
2. **精准断言要求**：
   * 禁止使用单纯的 `assertNotNull(result)` 来充当整个复杂业务流的唯一断言。
   * 必须对返回结果的**关键状态、核心字段值**进行精确的 `assertEquals` 比对。
3. **异常路径覆盖**：
   * 关键业务路径必须同时编写“成功通路测试”与“异常/边界值校验测试”，确保错误流在预期内被捕获。

---

## 3. 测试临时文件与环境幂等约束 (Idempotency)

1. **临时目录隔离**：测试过程中若需要创建临时文件、临时配置或模拟数据流，必须使用测试框架提供的临时目录机制（如 JUnit 的 `@TempDir` 或平台原生临时目录）。
2. **零副作用残留**：**严禁**在项目根目录下或测试资源目录外生成持久的临时文件。测试运行结束后，所有生成的临时文件必须随测试会话的结束被自动清理，确保测试的幂等性。

---

## 4. 测试验证、日志限制与自愈纠错

1. **测试定位**：运行测试时，只能精准运行当前 WP 修改范围内的类测试，禁止触发项目全量构建。
2. **Error 提取协议**：当测试失败时，Agent 应主动提示人类仅提供 Error 关键的 Stacktrace 和 Assertion 失败信息，过滤无关的构建状态日志。
3. **纠错熔断机制 (Max Retries)**：设定最大局部纠错轮数为 **3 轮**。若 3 轮自我修复后测试依然失败，Agent 必须主动终止修改并挂起，提示人类介入排查，严禁死循环尝试以避免消耗 Token。
4. **增量修复与防污染原则**：在修复失败的测试时，修改动作必须严格限制在当前 WP 允许的目标文件内。**严禁**为了通过测试而反向修改周围已稳定的 Domain 核心层接口或已 Completed 的其它模块契约。
