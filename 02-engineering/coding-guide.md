# Coding 指导与验收

1. 先确认迁移与交接状态，读取 `architecture.md`、`integration.md` 和产品需求；不要在本轮骨架中直接生成 src、平台目录、模块或虚假占位业务。
2. 初始化时在 app 容器一次创建 android/ios/ohos，锁定 FVM 与 Melos；在 mini-program 容器建立 Taro/pnpm 多包结构，只启用 weapp。官网保持静态站点。依赖版本以当次官方基线和锁文件记录，不使用不确定 latest。
3. 从本地库存、检查周期与整理状态开始，分别实现持久化和能力适配器。协议同意门禁必须先于任何联网身份和遥测；先应用权限解释再触发系统请求，拒绝/受限/返回系统设置可闭环。
4. 采用官方 SDK 接入平台身份、反馈、遥测；事件目录为 `01-product/mvp/telemetry-events.json`。更新为三类端与显式渠道上下文；只记录白名单枚举，不记录照片、食材、库存 ID、反馈正文、联系方式、Token 或硬件标识。单批 50、队列 100、有界重试，撤回统一隐私授权后停止并清空队列；无单独分析开关。
5. 后续 coding 指定实际字符串、离线协议、同意存储、SDK bootstrap、公共 telemetry context 路径并回填 project.yaml，不能仅保留文档承诺。
6. 验证核心规则的真实行为：记录 CRUD/跨区移动、历史恢复/撤销、周期去重、同日合并/跨日、部分及全部处理、改期与旧周期隔离、重启持久化。按 MVP 验收空状态，不将演示种子数据当正式首装状态。
7. 三端执行分析/构建与真机权限、拍摄、多选、通知点击、数据重启验收；微信执行类型检查、领域测试、架构边界检查、weapp 构建及开发者工具/真机检查。官网下载/法律/联系/返回路径和手机桌面显示需验证。不可运行的环境明确记录，不能用 Web 截图替代原生验收。
8. 视觉逐屏比较 Figma 与客户端截图，检查尺寸、居中、色值、图标、记录、弹窗边距与顶部权限解释；独立拍摄页不能退回弹窗。当前 preview 与 Figma 的差异不自动判定通过。

后续具体工程变更遵守命中的 coding skill 和用户批准流程。本轮为 fl-mvp-to-project 的资产交接，不额外要求一次 `spec approved` 才能生成指导文件。
